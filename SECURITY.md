# Security policy

This project is a local educational app, not a production service. Only the current
`main` branch is maintained. There is no guaranteed response-time commitment.

Before public launch, maintainers should enable GitHub private vulnerability reporting.
If the repository's Security tab offers **Report a vulnerability**, use that private path
with affected revision, impact and a minimal synthetic reproduction. Do not include live
credentials, private data or an exploit against someone else's service.

If private reporting is unavailable, open a minimal issue asking maintainers to provide
a private reporting channel; do not post exploit details or secrets publicly. There is
no invented security email address in this starter.

Scans detect some known issues, not all vulnerabilities. Review source logic, dependencies,
permissions, configuration, and logs. Rotate/revoke exposed credentials; removing them
from the latest file is not sufficient.
